# InfoQ 管理端操作

本技能只负责一件事：管理端真实运营/维护页面操作的 SOP。它不执行 E2E 自动化，不替代后端验证，不主导数据库侧数据修复，也不默认写入共享环境。

## 场景选择

1. 用户、角色、菜单、部门、岗位、字典、参数、公告、OSS、定时任务等后台模块的真实操作规划，使用本 skill。
2. 权限按钮巡检、菜单可见性核对、测试数据维护的页面侧操作，使用本 skill。
3. 需要浏览器执行、截图或 console/pageerror 证据时，调用 `infoq-browser-automate`。
4. 需要真实验证码登录、动态路由 smoke 或 CRUD E2E 模式时，改用 `infoq-admin-e2e`。
5. 需要 SQL、数据库、Redis、数据修复、迁移、幂等或 API/UI/DB 一致性验证时，改用 `infoq-data-ops`。
6. 需要后端接口、登录链路或运行态验证时，改用 `infoq-backend-verify`。

## 执行顺序

1. 判定范围：确认模块、操作类型、环境、账号角色和是否涉及写入。
2. 只读探测：先读取菜单、权限、列表、详情或接口只读信息；不要直接修改。
3. 目标枚举：列出目标记录名称、ID、所属模块、影响用户、关联角色、上下游数据和预期结果。
4. 门禁确认：删除、批量更新、启停任务、权限变更、测试数据清理和导出都必须先明确风险、cleanup、回滚条件和验证命令；数据库侧修复转交 `infoq-data-ops`。
5. 执行验证：操作后用列表/详情/API 或必要的 `infoq-data-ops` 数据侧核对结果，并保留证据路径。
6. 收口记录：把临时 payload、导出、截图、日志和检查结果放入 `doc/tmp/infoq-admin-ops/`。

## 默认证据目录

```text
doc/tmp/infoq-admin-ops/
```

## 护栏

- 默认不对共享环境执行写入操作。
- 没有目标 ID、影响范围、cleanup 和回滚条件时，不执行删除、批量、权限或任务启停操作。
- 不把 E2E 通过当成真实运营操作完成；运营操作必须有操作后只读核对。
- 不把后端接口 smoke 当成后台权限巡检；权限巡检必须说明账号角色、菜单路径和按钮权限。
- 不把管理端页面操作 SOP 用作 SQL、迁移或数据库侧数据修复；此类任务使用 `infoq-data-ops`。
- 导出文件、临时 payload 和截图不能散落到仓库其他路径。
