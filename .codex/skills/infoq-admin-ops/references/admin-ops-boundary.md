# 管理端操作边界

## 职责

`infoq-admin-ops` 负责真实后台运营/维护页面操作的流程约束：

- 用户、角色、菜单、部门、岗位、字典、参数、公告、OSS、定时任务等模块操作规划。
- 权限按钮巡检和菜单可见性核对。
- 测试数据维护的页面侧操作、导出前后页面/API 核对。
- 删除、批量、权限、任务启停、清理和修复动作的门禁。

## 不负责

- 管理端 E2E 自动化：使用 `infoq-admin-e2e`。
- 浏览器底层执行、截图和 console/pageerror 证据：使用 `infoq-browser-automate`。
- SQL、数据库、Redis、数据修复、迁移、幂等和 API/UI/DB 一致性验证：使用 `infoq-data-ops`。
- 后端接口、登录链路、Redisson OSS 验证：使用 `infoq-backend-verify`。
- React/Vue admin 或 weapp 单测、构建和运行态验证：使用 `infoq-frontend-verify`。

## 写入门禁清单

写入前必须列出：

- 环境：local、dev、test 或其他明确环境。
- 账号角色：执行账号、验证账号和角色权限。
- 目标：模块、记录名称、ID、页面筛选条件。
- 影响：关联用户、角色、菜单、任务、字典项或业务数据。
- cleanup：如何恢复测试数据或撤销临时记录。
- 回滚：失败后恢复路径、脚本或手工步骤。
- 验证：操作后只读查询、页面核对、API 核对或数据库只读核对。

## 默认策略

- 共享环境默认只读。
- 删除和批量操作默认禁止，除非用户明确确认目标集。
- 定时任务启停必须说明任务名称、执行计划、影响窗口和恢复方式。
- 权限变更必须用至少两个角色核对：拥有权限的角色和不应拥有权限的角色。
- 数据库侧修复或 SQL 迁移必须切换到 `infoq-data-ops`。
