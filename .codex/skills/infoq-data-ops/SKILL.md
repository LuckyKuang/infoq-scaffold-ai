# InfoQ 数据运维

本技能只负责一件事：数据库、缓存和基础数据侧的数据运维/治理 SOP。它不替代管理端页面操作，不主导后端行为验证，也不绕过 OpenSpec 或 SQL migration 规则。

## 场景选择

1. SQL 增量脚本、表结构或初始化数据变更规划，使用本 skill。
2. 数据修复、批量更新、测试数据清理、字典/参数/菜单/权限基础数据数据库侧核对，使用本 skill。
3. MySQL / Redis 只读诊断、数据一致性排查、API/UI/DB 三方核对，使用本 skill。
4. 管理端页面上的用户、角色、菜单、字典、公告、OSS、定时任务等真实操作，改用 `infoq-admin-ops`。
5. 后端接口、登录、Mapper XML、Redisson OSS 或运行态 smoke 验证，改用 `infoq-backend-verify`。
6. 生产或共享环境数据变更、SQL 迁移、批量修复，必须联动 `infoq-delivery-workflow`。

## 执行顺序

1. 判定范围：确认是 schema、初始化数据、修复脚本、测试数据、Redis key、只读诊断，还是一致性核对。
2. 只读探测：先读取 SQL migration、Mapper/XML、实体、接口、页面路径、当前数据和环境配置；不要先写入。
3. 目标枚举：列出环境、表/字段/key、记录 ID、筛选条件、影响模块、关联用户/角色/菜单/任务和预期结果。
4. 方案设计：写清 SQL 或 Redis 操作的幂等性、重复执行行为、事务边界、锁/性能影响、回滚脚本和验证查询。
5. 门禁确认：共享环境、生产数据、批量更新、删除、权限、菜单、任务、字典和参数变更必须先确认风险和 rollback。
6. 执行验证：执行后用只读 SQL/API/UI 或 Redis 查询核对结果，并保留证据路径。
7. 收口记录：把临时 SQL、查询结果、导出、日志和检查结果放入 `doc/tmp/infoq-data-ops/`。

## 默认证据目录

```text
doc/tmp/infoq-data-ops/
```

## SQL migration 规则

- `sql/infoq_scaffold_2.0.0.sql` 是冻结初始化基线，永远不要修改。
- 新增、修改、删除表结构或初始化数据，只能新增 `sql/infoq_scaffold_update_YYYYMMDD.sql` 增量脚本。
- 若误改初始化 SQL，必须立即回退该文件，并把变更迁移到当前日期增量脚本。
- 增量脚本必须考虑幂等性、重复执行安全、回滚路径和与现有数据的兼容性。

## 护栏

- 默认不对共享环境执行写入操作。
- 没有目标表/key、筛选条件、影响范围、验证查询和回滚脚本时，不执行数据写入。
- 禁止把后端 smoke 通过当成数据修复完成；数据修复必须有数据侧只读核对。
- 禁止把管理端页面保存成功当成数据库一致性完成；关键数据必须核对 API/UI/DB 至少两个视角。
- 禁止直接修改冻结初始化 SQL。
- 临时 SQL、导出、查询结果和日志不能散落到仓库其他路径。
