# 管理端页面运维与操作门禁

本文件是管理端页面运维与权限巡检的门禁说明，用于在真实管理端页面上做运营维护、权限巡检和测试数据维护时执行门禁、影响枚举、操作后验证与证据留存。

## 1. 适用与不适用

适用：

- 用户、角色、菜单、部门、岗位、字典、参数、公告、OSS、定时任务等后台模块的真实页面操作规划与执行。
- 权限按钮巡检、菜单可见性核对、测试数据维护的页面侧操作。

不适用：

- 需要通用浏览器执行、截图或 console/pageerror 证据：使用 `test-cli`。
- 需要真实验证码登录、动态路由 smoke 或 CRUD E2E 自动化：使用本 skill 的 `run_admin_e2e.mjs` / `run_admin_crud_e2e.mjs`。
- SQL、数据库、Redis、数据修复、迁移、幂等或 API/UI/DB 一致性核对：改用 `docs/DATA-OPS.md`。
- 后端接口、登录链路或运行态验证：改用 `tools/verify`。

## 2. 执行顺序

1. 判定范围：确认模块、操作类型、环境、账号角色和是否涉及写入。
2. 只读探测：先读取菜单、权限、列表、详情或接口只读信息；不要直接修改。
3. 目标枚举：列出目标记录名称、ID、所属模块、影响用户、关联角色、上下游数据和预期结果。
4. 门禁确认：删除、批量更新、启停任务、权限变更、测试数据清理和导出必须先明确风险、cleanup、回滚条件和验证命令；数据库侧修复转交 `docs/DATA-OPS.md`。
5. 执行验证：操作后用列表/详情/API 或必要的 `docs/DATA-OPS.md` 数据侧核对结果，并保留证据路径。
6. 收口记录：把临时 payload、导出、截图、日志和检查结果放入 `tmp/test-cli/e2e/page-ops/`。

## 3. 写入门禁清单

写入前必须列出：

- 环境：local、dev、test 或其他明确环境。
- 账号角色：执行账号、验证账号和角色权限。
- 目标：模块、记录名称、ID、页面筛选条件。
- 影响：关联用户、角色、菜单、任务、字典项或业务数据。
- cleanup：如何恢复测试数据或撤销临时记录。
- 回滚：失败后恢复路径、脚本或手工步骤。
- 验证：操作后只读查询、页面核对、API 核对或数据库只读核对。

## 4. 护栏

- 默认不对共享环境执行写入操作；共享环境默认只读。
- 没有目标 ID、影响范围、cleanup 和回滚条件时，不执行删除、批量、权限或任务启停操作；删除和批量操作默认禁止，除非用户明确确认目标集。
- 定时任务启停必须说明任务名称、执行计划、影响窗口和恢复方式。
- 权限变更必须用至少两个角色核对：拥有权限的角色和不应拥有权限的角色。
- 不把 E2E 通过当成真实运营操作完成；运营操作必须有操作后只读核对。
- 不把后端接口 smoke 当成后台权限巡检；权限巡检必须说明账号角色、菜单路径和按钮权限。
- 不把管理端页面操作 SOP 用作 SQL、迁移或数据库侧数据修复；此类任务使用 `docs/DATA-OPS.md`。
- 导出文件、临时 payload 和截图不能散落到仓库其他路径。
