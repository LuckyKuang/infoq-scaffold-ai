# CRUD E2E 模式

## 查询

适用：列表页、日志页、配置页。

步骤：

1. 完成真实登录或复用已登录态。
2. 打开目标模块路由。
3. 等待表格、树或配置面板出现。
4. 输入查询条件。
5. 点击查询。
6. 断言结果区域刷新，且无阻断性 console error。

## 新增

适用：用户、角色、部门、岗位、字典、公告、客户端、邀请码等。

步骤：

1. 使用 `e2e_` 前缀生成唯一测试数据。
2. 打开新增弹窗或页面。
3. 填写必填项。
4. 提交。
5. 断言成功提示和列表可查；API 与 DB 必须恰好存在一条本 run 活动记录，关键字段及主键一致。
6. 记录 cleanup 主键或唯一键。

## 编辑

步骤：

1. 先创建或定位 `e2e_` 测试数据。
2. 打开编辑入口。
3. 实际修改一个可编辑字段，不能重复选择原状态制造编辑通过；client 用 `activeTimeout` 从 `1800` 改为 `1801`。
4. 提交。
5. 对照编辑预期同时断言 API/DB 字段及记录身份，不以请求完成或快照存在作为通过条件。

## 删除

步骤：

1. 只删除当前用例创建的 `e2e_` 数据。
2. 触发删除并确认。
3. 断言 API 与 DB 中当前 run 的全部精确键均无活动记录；查询异常或不完整分页必须失败。
4. 删除失败时输出人工回滚提示。

## 导入导出

- 导入必须使用临时文件并在 `tmp/` 下留存。
- 导出必须断言文件响应或下载事件。
- 不得把下载文件散落到仓库根目录。

## 权限按钮

每个模块至少设计两类断言：

- 有权限账号：按钮可见且可触发。
- 无权限账号：按钮不可见或触发后被拒绝。

如多账号矩阵尚未建立，先记录为延期，不伪造权限覆盖。

## 工具隔离回归 SOP

触发条件：修改数据命名、API/DB 断言、分页清理、登录加密、浏览器或自管栈退出流程。先以当前模块的正常与失败场景验证最小闭环，再运行受影响工具套件；无需启动真实后端、Redis、数据库或 Chromium。

```bash
node skills/test-cli/scripts/test_admin_crud.mjs
node skills/test-cli/scripts/test_browser_runtime.mjs
node skills/test-cli/scripts/test_redis_captcha_seed.mjs
node tools/test_skill_runtime.mjs
```

CRUD 套件覆盖业务字段/主键不一致、未发生编辑、删除残留、DB 未执行或报错、列表协议/分页异常、双端短用户名随机量与中断清理；还须验证 `--keep-stack-after` 在报告落盘失败或期间中断时撤销保留，清理失败不能覆盖原始错误。浏览器套件用隔离 Playwright fixture 验证 HTTP/console 失败、关闭失败与 DevTools owned 进程退出；登录套件使用回环 HTTP/RESP 及真实 RSA/AES 编解码验证协议。共享 runtime 套件验证超时/取消后的进程树收口。

完成后对改动入口执行 `node --check`、编码检查和 diff 审查，临时证据放 `tmp/`。禁止用 `rows=[]` 掩盖查询错误、用相同值编辑凑通过、通过截断随机量或按整个 `e2e_` 前缀删除数据、以及以假浏览器测试替代真实 DOM/数据库验收。真实环境回归仍须按测试政策单独授权并留证。
