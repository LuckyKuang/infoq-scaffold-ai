# Cleanup 策略

## 必须清理的场景

- 新增用户、角色、部门、岗位、字典、公告、客户端、邀请码。
- 上传文件。
- 新增或修改 OSS 配置。
- 新增定时任务。
- 修改可持久化配置。
- 为在线强退创建的 `e2e_` 用户和会话。

## 清理顺序

1. 优先通过 UI 删除当前用例创建的数据。
2. UI 清理失败时记录 API 或数据库人工回滚提示。
3. 仍无法清理时在报告中标记 residual risk。

## 失败处理

清理失败不得被静默忽略。报告必须包含：

- 模块名。
- 测试数据唯一键。
- 已执行的清理动作。
- 失败原因。
- 人工回滚建议。

## 禁止行为

- 不删除非 `e2e_` 数据。
- 不批量清空表。
- 不清理冻结初始化 SQL。
- 不为了清理方便修改产品删除逻辑。
