# InfoQ 数据运维

本文件只负责一件事：数据库、缓存和基础数据侧的数据运维/治理 SOP。它不替代管理端页面操作，不主导后端行为验证，也不绕过 OpenSpec 或 SQL migration 规则。

## 场景选择

1. SQL 增量脚本、表结构或初始化数据变更规划，使用本文件。
2. 数据修复、批量更新、测试数据清理、字典/参数/菜单/权限基础数据数据库侧核对，使用本文件。
3. MySQL / Redis 只读诊断、数据一致性排查、API/UI/DB 三方核对，使用本文件。
4. 管理端页面上的用户、角色、菜单、字典、公告、OSS、定时任务等真实操作，改用 `test-cli` 的页面运维门禁（`skills/test-cli/references/ops/page-ops-guardrails.md`）。
5. 后端接口、Mapper XML、Redisson OSS 或运行态 smoke 验证改用 `tools/verify`；登录/鉴权验证改用 `test-cli` 的验证码种子登录。
6. 生产或共享环境数据变更、SQL 迁移、批量修复，必须联动 `docs/DELIVERY-WORKFLOW.md`。

## 执行顺序

1. 判定范围：确认是 schema、初始化数据、修复脚本、测试数据、Redis key、只读诊断，还是一致性核对。
2. 只读探测：先读取 SQL migration、Mapper/XML、实体、接口、页面路径、当前数据和环境配置；不要先写入。
3. 目标枚举：列出环境、表/字段/key、记录 ID、筛选条件、影响模块、关联用户/角色/菜单/任务和预期结果。
4. 方案设计：写清 SQL 或 Redis 操作的幂等性、重复执行行为、事务边界、锁/性能影响、回滚脚本和验证查询。
5. 门禁确认：共享环境、生产数据、批量更新、删除、权限、菜单、任务、字典和参数变更必须先确认风险和 rollback。
6. 执行验证：执行后用只读 SQL/API/UI 或 Redis 查询核对结果，并保留证据路径。
7. 收口记录：把临时 SQL、查询结果、导出、日志和检查结果放入 `tmp/data-ops/`。

## 写入门禁清单

数据写入前必须列出：

- 环境：local、dev、test、staging、prod 或其他明确环境。
- 连接来源：配置文件、MCP、只读账号或手工执行入口。
- 目标：表、字段、Redis key、记录 ID、筛选条件。
- 影响：关联用户、角色、菜单、部门、任务、字典项、参数或业务数据。
- SQL / Redis 操作：预览查询、写入语句、事务边界和预计影响行数。
- 幂等性：重复执行的结果，以及如何避免重复插入或重复更新。
- cleanup：测试数据或临时记录如何清理。
- 回滚：失败后的恢复 SQL、脚本或手工步骤。
- 验证：操作后只读 SQL、API 核对、页面核对或 Redis 查询。

```text
tmp/data-ops/
```

## SQL migration 规则

- 冻结初始化基线是 `sql/` 下唯一的 `infoq_scaffold_x.y.z.sql`（当前为 `sql/infoq_scaffold_3.0.0.sql`），永远不要修改。
- 新增、修改、删除表结构或初始化数据，只能新增 `sql/infoq_scaffold_update_YYYYMMDD.sql` 增量脚本。
- 若误改初始化 SQL，必须立即回退该文件，并把变更迁移到当前日期增量脚本。
- 增量脚本必须考虑幂等性、重复执行安全、回滚路径和与现有数据的兼容性。

执行前记录目标实例/库、备份标识、迁移文件及校验值、已应用状态和预计影响行数；按日期及同日脚本内顺序仅执行尚未应用的迁移。当前仓库没有统一自动迁移台账，文件存在不代表已执行；已发布或已执行的增量不得改写，应新增补偿脚本。

MySQL DDL 可能隐式提交，不能用外层事务或 `ROLLBACK` 承诺撤销建表、改列或删表。先在兼容数据副本上验证锁等待、执行耗时、应用新旧版本兼容及恢复步骤；大表写入按有界批次执行，保留稳定筛选条件、预期与实际影响行数。超出目标集、行数不符、锁等待/延迟超预算或关键验证失败时停止后续批次，不盲目重跑。

备份必须覆盖数据库及关联对象文件/配置，限制访问并确认可恢复；仅有备份文件不等于恢复演练通过。缓存失效、权限/会话索引、Quartz 发布批次等后续动作只针对已枚举对象执行，不全库 flush。恢复数据可能覆盖发布后的新写入，必须单独确认恢复点与数据损失窗口，不能把应用 jar 回滚当成数据回滚。

只读诊断同样需要资源预算：使用最小权限账号、参数化或已审阅的查询、限定字段/行数与超时，避免生产全表扫描、无界导出或 Redis `KEYS *`。MCP 的只读环境变量和工具白名单不代替数据库/Redis ACL；具体配置边界见 `docs/MCP-SERVERS.md`。

## 护栏

- 默认不对共享环境执行写入操作；共享环境默认只读。
- 没有目标表/key、筛选条件、影响范围、验证查询和回滚脚本时，不执行数据写入；删除、truncate、批量 update、批量 delete 和权限/菜单/任务相关数据变更默认禁止，除非用户明确确认目标集。
- 数据修复必须先有只读 preview，再有 write plan，最后才执行。
- 禁止把后端 smoke 通过当成数据修复完成；数据修复必须有数据侧只读核对。
- 禁止把管理端页面保存成功当成数据库一致性完成；权限、菜单、字典和参数等关键数据必须核对 API/UI/DB 至少两个视角。
- 临时 SQL、导出、查询结果和日志不能散落到仓库其他路径。
- 证据默认只记录迁移标识、计数、脱敏差异和结论，不保存密码、token、RSA 私钥或完整生产个人数据。必须导出敏感数据时使用受控位置、访问权限和明确保留/销毁期限；不得纳入 Git。
