# 返回字段翻译规范

## 目标

定义注解字段的上下文隔离、翻译失败语义及安全诊断。

## 要求

### 要求：返回字段翻译显式失败并保护原值

带翻译注解的字段必须使用对应类型与 mapper 来源完成展示值翻译。翻译实现缺失、mapper 读取异常或翻译执行失败时，序列化必须显式失败，必须 不把原值回写成成功响应，也不得仅在日志中记录失败后继续。

#### 场景：翻译成功和空来源

- 当翻译实现可用且 mapper/source 有值或为 null。
- 则系统必须输出当前字段的翻译结果；合法 null 来源必须输出 null。
- 并且真实 Jackson 序列化必须保持不同字段的 type/mapper/other 上下文独立，必须 不因共享 serializer 可变状态串用注解。

#### 场景：实现缺失或执行失败

- 当翻译类型未注册、mapper 无法读取或实现抛出异常。
- 则当前序列化必须明确失败且可被异常处理链定位到翻译阶段；必须 不输出源 ID、源字符串或敏感原值冒充翻译结果。
- 并且未带翻译注解的普通字段必须继续使用正常 serializer。

### 要求：翻译诊断不得泄露值

翻译错误日志与向客户端暴露的错误必须仅包含安全的阶段、类型、字段和异常类别，必须 不包含原值、翻译结果、秘密或可能携带原值的异常 message/堆栈内容。

#### 场景：依赖异常携带敏感原值

- 当翻译依赖抛出的异常 message 包含 token、邮箱、对象凭据或输入原值。
- 则日志及公开错误必须不含这些值，同时必须保留安全关联上下文供排障。
