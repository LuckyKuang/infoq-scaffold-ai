# 菜单与权限规范

## 目标

定义当前仓库的后台菜单真值、菜单维护校验，以及权限标识的消费方式。

## 要求

### 要求：按用户返回菜单路由
后台动态路由必须以后端菜单树为真值。

#### 场景：加载后台菜单

- 当已登录用户调用 `/system/menu/getRouters` 时
- 则系统必须按当前用户的可见菜单树返回 `RouterVo` 列表
- 并且返回结果必须作为管理端动态路由的真值来源

### 要求：菜单配置校验
管理员维护菜单时必须遵守名称、路由和外链配置校验。

#### 场景：新增或修改菜单

- 当管理员新增或修改菜单时
- 则菜单名称必须在同一上级菜单下唯一
- 并且目录/菜单的同级路由路径、根路径及派生路由名称必须通过 `checkRouteConfigUnique` 校验；按钮不参与路由名称冲突校验
- 并且当 `isFrame` 表示外链时，`path` 必须以 `http://` 或 `https://` 开头
- 并且上级菜单不得选择自己

### 要求：删除保护
菜单删除必须阻断破坏性场景。

#### 场景：单项删除菜单

- 当菜单存在子菜单或已经分配给角色时
- 则系统必须拒绝删除

批量 `DELETE /system/menu/cascade/{menuIds}` 是另一条契约：阻止选中集合之外残留子菜单，并在事务内删除选中菜单及角色菜单关联；它不会因为已分配角色而拒绝。调用方应把这条链路视为会撤销角色菜单关系的破坏性操作。

### 要求：权限标识消费
路由和页面级权限判断必须使用会话返回的权限标识。

#### 场景：客户端消费权限

- 当 `/system/user/getInfo` 返回 `permissions` 与 `roles` 时
- 则前端路由过滤和按钮级鉴权必须以这些权限标识为准

菜单管理的列表、详情、新增、修改及两种删除还要求超级管理员角色和相应 `system:menu:*` 权限；`getRouters` 返回当前用户菜单，不等同于菜单管理授权。依据为 `SysMenuController`、`SysMenuServiceImpl` 与 `SysMenuMapper`。
