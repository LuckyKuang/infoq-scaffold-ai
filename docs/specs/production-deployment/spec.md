# 生产部署与恢复规范

## 目标

定义 Linux Docker 生产基线的受控构建、HTTPS、网络、权限迁移与隔离恢复。

## 要求

### 要求：生产配置与 RSA 受控构建

Linux Docker 生产部署和生产前端构建必须在副作用前验证必需秘密、独立配置来源及 RSA 配对；已知仓库示例值、缺项、格式无效或不匹配必须显式失败。`VITE_APP_ENCRYPT=true` 时，构建必须使用与后端对应且至少 2048 位的两组 RSA 密钥：前端公钥匹配后端请求解密私钥，前端私钥匹配后端响应加密公钥；必须 交叉校验两组方向，必须 不误要求前端两把 key 互为一对，也不得依赖宿主运行时变量修改已生成的浏览器包。

#### 场景：受控密钥进入前端构建

- 当构建 Docker 前端或可发布前端压缩包。
- 则构建入口必须提供受控配置注入并执行匹配校验，必须 拒绝示例 RSA 或缺失密钥。
- 并且证据必须记录脱敏来源/指纹与结果，必须 不打印秘密；文档必须明确浏览器包内的密钥不是服务端秘密屏障。

#### 场景：无效生产凭据

- 当DB、Redis、MinIO、token、管理员或 RSA 仍缺失、使用示例值或不能确认来源。
- 则生产预检必须明确失败并列出配置项名称，必须 不启动部署或声称生产就绪。
- 并且隔离开发示例模式必须显式区分，必须 不自动降级生产校验。

### 要求：持久 HTTPS 与最小网络暴露

生产网关必须使用外部受控证书提供 HTTPS，并验证证书与私钥匹配、有效期和域名；prepare/start/redeploy必须保留受控 TLS 配置。基础设施、管理控制台和应用直连端口必须默认仅内部或 loopback，公网入口必须限于经配置的网关。

#### 场景：重建网关配置

- 当已配置有效 TLS 的部署执行 prepare、start 或 redeploy。
- 则渲染后的配置必须保留 HTTPS 与证书引用，HTTP必须重定向 HTTPS 或按显式策略拒绝。
- 并且仅映射 443 或写 HTTPS 公共地址但无 TLS 的配置必须失败；实际证书链和端口暴露必须独立验证。

### 要求：权限迁移具备归属与恢复边界

已有数据目录的迁移必须根据目标镜像实际 UID/GID 与挂载需要生成方案；必须 先核验路径、符号链接、权限、资源归属及备份，不得盲目递归修改未知/共享目录，不得使用 `0777` 解决写入问题。

#### 场景：旧目录迁移和失败恢复

- 当旧部署目录不满足目标镜像读写权限。
- 则工具必须默认预览变更，显式执行后保留原 owner/mode 恢复证据，并验证重启与写入。
- 并且目标或归属不符必须在变更前失败；恢复失败必须显式阻塞上线。

### 要求：隔离恢复与应用回滚可执行

运维工具必须提供可复用的备份完整性检查、隔离恢复与应用版本回滚路径，默认预览目标/影响，写入必须显式执行且核验 owned 隔离资源。恢复验证必须不以文件存在或进程启动代替数据一致性与业务可用性。

#### 场景：隔离恢复数据库与对象

- 当运维人员使用备份在独立目标演练恢复。
- 则工具必须核验备份校验和、目标隔离、必要凭据、实际还原结果及关键数据一致性，并记录耗时/恢复点。
- 并且共享目标、未知归属、缺失备份或中途失败必须停止并留存证据，不删除源数据。

#### 场景：应用回滚

- 当新版本 readiness 或关键业务检查失败。
- 则工具必须基于已核验旧镜像/产物与兼容配置执行授权的隔离回滚，保留数据并重新验证 readiness 与业务。
- 并且SQL 或不兼容数据变更必须保持独立恢复审批，不能自动反向迁移。
